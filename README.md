# Метеокарта — покадровый просмотр

Сервер скачивает `phenomena.gif`, без сохранения старых копий на диск разбирает GIF на PNG-кадры и отдаёт их браузеру. В браузере доступны стрелки, ползунок, автовоспроизведение, масштабирование, перетаскивание и мобильные жесты.

## Локальный запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm start
```

Откройте <http://localhost:3000>. Для разработки с автоперезапуском: `npm run dev`.

## Как обновляются данные

- При старте сервер сразу получает GIF.
- Затем обновляет его по UTC в минуты `03, 13, 23, 33, 43, 53`.
- Кнопка в шапке запускает внеплановую проверку (не чаще раза в 30 секунд).
- Все запросы к источнику и API идут без кэша, а адрес GIF дополняется уникальным параметром.
- Версия набора кадров вычисляется из содержимого GIF. Клиент принимает кадры только текущей версии.
- Если содержимое источника не менялось 35 минут, сервер перестаёт отдавать кадры. Так очень старые данные не могут незаметно остаться на экране. Порог меняется переменной `STALE_AFTER_MINUTES`.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `PORT` | `3000` | Порт веб-сервера |
| `SOURCE_URL` | URL Meteoinfo | Другой источник GIF |
| `STALE_AFTER_MINUTES` | `35` | Когда неизменившиеся данные считать старыми |
| `FETCH_TIMEOUT_MS` | `25000` | Тайм-аут загрузки источника |

## Деплой через Docker

```bash
docker build -t meteo-viewer .
docker run -p 3000:3000 --restart unless-stopped meteo-viewer
```

Для публикации на Render, Railway, Fly.io или другом сервисе подключите репозиторий и выберите Dockerfile. Контейнер слушает переменную `PORT`. Нужен один постоянно работающий экземпляр; сервер не требует базы или постоянного диска.

Для проверки состояния используйте `GET /health`: код `200` означает, что свежие кадры доступны, `503` — источник ещё загружается или данные признаны устаревшими.
